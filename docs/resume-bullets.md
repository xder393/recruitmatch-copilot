# 简历与面试表述

## 推荐项目名

RecruitMatch Copilot｜多岗位可解释智能推荐平台

## 可直接使用的简历描述

- 面向企业招聘初筛场景设计多租户 RecruitMatch Copilot，打通岗位版本管理、PDF/DOCX/TXT 简历解析、岗位 Top 3 推荐与招聘人员反馈闭环；通过 JWT 租户上下文和仓储级过滤防止跨企业数据访问。
- 在 `rules-v1` 可解释基线上实现 `hybrid-v1`，固定以 80% 规则分和最多 20% 语义项目分重排；语义分必须同时引用当前简历与 JD，未知/越权引用贡献归零并显式降级。
- 构建租户级招聘 RAG：知识文档幂等上传、精确偏移分块、本地 BGE Embedding、generation-safe 重建、停用过滤和稳定 Citation ID；结构化模型输出经 Pydantic 与引用集合双重校验。
- 建立两套各 150 条的确定性合成回归集，对规则/LLM/混合路径统计抽取、Top-K、引用有效率、幻觉率、延迟、Token 与成本；`hybrid-v1` 合成集 Top-1 95.33%、Top-3 98%、引用有效率 100%，明确不等同于真实招聘效果。
- 使用 FastAPI、SQLAlchemy/Alembic、PostgreSQL、Redis/Celery 和 Docker Compose 实现模块化单体；为上传幂等、损坏文档、任务状态、租户 IDOR、岗位版本、推荐排序和反馈 API 建立自动化测试与 CI 门禁。

## 面试讲解顺序

1. 业务问题：一份简历可能适合多个岗位，招聘人员需要推荐依据而不是黑盒分数。
2. 核心不变量：租户隔离、岗位版本不可变、所有技能结论有证据、未知不推断、人工最终决策。
3. 数据流：上传幂等 → 异步解析 → 画像 → active 岗位 → Top 3 → 反馈。
4. 算法取舍：规则基线保障可解释与可用性，RAG 只补充项目语义；20% 上限和双侧引用约束控制模型风险。
5. 工程证据：迁移、状态机、稳定错误码、审计、健康检查、CI 和合成评测。
6. 局限：没有真实招聘专家数据、没有生产用户、没有证明商业收益。

## 禁止使用的表述

- “已应用于企业生产”或“服务大量用户”。
- 只说“准确率 95.33%”而不说明它是 Fake Model 驱动的合成 AI 回归基准。
- “自动筛选/淘汰候选人”。
- “达到 99.99% SLA”或虚构并发、收入、成本下降数据。
- “完全消除招聘偏见”。
