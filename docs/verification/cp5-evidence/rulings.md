# Rulings I made

CP5 全部裁决 R1–R19，按发生顺序列出。完整原始理由见 controller-final-ledger.md；此表不代替冻结设计。

| ID | 裁决 | 判断有误时的代价 |
| --- | --- | --- |
| R1 | 在不依赖 SDK 的事件接口上补充数值和操作范围，保留旧接口兼容。 | 重做接口及调用方。 |
| R2 | 覆盖必要埋点和日志边界，数据库安全审计独立保留。 | 增加适配器和测试维护。 |
| R3 | 使用行为测试、真实后端正向输出及隐私反例验证。 | 增加测试启动和执行时间。 |
| R4 | 由宿主机仅编排专用测试栈故障，不挂 Docker Socket，不用真实模型。 | 维护测试编排脚本。 |
| R5 | 清理失败复用 artifact.operation，不增加规范外指标。 | 调整事件与查询映射。 |
| R6 | 每个实际遥测写入实例生成独立随机 Resource UUID，覆盖替换和 prefork。 | 重做生命周期和聚合，影响历史指标连续性。 |
| R7 | 拆分框架、上下文、包装器和探针职责。 | 调整模块组织与导入。 |
| R8 | 公共框架埋点只路由到明确活跃的实例，无实例则 Noop。 | 重做生命周期适配，可能暂时缺少遥测。 |
| R9 | 采用 25 秒有界观测快照、失败失效和最新实例选择，未知不等于零。 | 重做快照/查询，并承担过期识别延迟。 |
| R10 | 失败尝试与安排重试允许重叠；完成只统计持久化发布。 | 修改埋点、查询和历史指标解释。 |
| R11 | 为既有到期重试分支添加有限枚举 retry_due。 | 修改枚举、查询和测试。 |
| R12 | 通过 Collector 内部 HTTP 检查实际健康，不伪造 Docker Health。 | 后续可能需要额外健康探测实现。 |
| R13 | 删除可选事件、链接、exemplar 和未批准模型标签，保留主遥测链路。 | 减少诊断细节并维护允许列表。 |
| R14 | 使用隔离的合成输入使真实 Prometheus 告警进入 Firing。 | 维护夹具；物理故障和容量实验仍需另做。 |
| R15 | 将受保护的 Worker/Beat 生命周期操作与 Collector 中断场景分开。 | 增加编排校验，短暂中断合成测试服务。 |
| R16 | Collector 失败指标分别计算速率，再合并查询结果。 | 修改两处查询及回归夹具。 |
| R17 | 用固定 Celery 版本的狭窄兼容适配将关闭诊断输出为常量 JSON。 | 升级时重新验证兼容耦合和信号行为。 |
| R18 | 对未提交但已审查的代码保存不可变快照，修复复核通过后再提交。 | 重建比较包并重新核对文件身份。 |
| R19 | 一轮最终修复后，将告警图例缺少 severity 明确列为非阻塞待办；不宣称五项全部解决。 | 判断紧急程度需额外查看；后续补图例和回归，规则维度变化时重审。 |

R9 的原始调查假设“同步 Gauge 会无限重复导出旧值”已被固定 SDK 版本的实验否定。最终采用有界可观测快照，是为了稳定重复观测、失败失效与 TTL 语义，不以已否定的假设作为缺陷结论。

R14 的实际 Firing 证明规则引擎接受了指定输入，不证明物理 Collector 饱和、后端故障或生产容量。R15 允许的操作范围不代表全部操作都已执行：已证明实际 Worker 进程重启及真实 SDK Gauge 写入实例替换，不宣称实际 Beat 进程重启。
