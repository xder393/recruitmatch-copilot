# RecruitMatch Evaluation and Delivery Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce repeatable recommendation metrics, operational health/audit evidence, a recruiter-facing web workflow, reproducible deployment, and truthful portfolio documentation.

**Architecture:** Evaluate the pure `rules-v1` engine against a versioned deterministic synthetic dataset; expose operational state through protected analytics and unprotected liveness/readiness endpoints; replace the legacy chat UI with a thin recruiter console that consumes `/api/v1`.

**Tech Stack:** Python, pytest, FastAPI, SQLAlchemy, Prometheus client, vanilla HTML/CSS/JS, Docker Compose, GitHub Actions

**Spec:** `docs/superpowers/specs/2026-08-19-recruitmatch-copilot-design.md`

## Global Constraints

- Synthetic data and heuristic labels are named as such everywhere.
- Metrics are generated by committed scripts, never typed into README by hand.
- Logs and analytics never expose resume text, passwords, or access tokens.
- Liveness does not depend on external models; readiness checks database connectivity.
- UI states that recommendations assist human review and do not make hiring decisions.
